We re-ran “Sparks of Weight-Space Programming”

An independent replication of the experiments in Takehi, Teoh, Zhang & Khattab (2026), using their released logs and weights.
By shapor · November 2026 · code, prompts and every model answer

The headline Qwen result is mostly about finishing, not math. The post says Astra's weight edit took Qwen3.5-0.8B from 7.9% to 48.1% on MATH-500. But in the post's setup the unedited model runs out of tokens on 93% of answers. The edit mainly makes it stop and answer. Turning thinking off does the same with no edit: we measured the unedited model at 45.2%, and the edited one at 44.2%.

Everything else we re-ran holds up. The hand-written MinAtar networks, the Go networks and the fixed car policy all came out within a few percent of the post. The car's “1,024 of 1,024 episodes” is one deterministic run repeated, though.

Reading small networks isn't unique to GPT-6 Astra. Given the same prompts blind, Claude Opus and Claude Fable identified the games and the diffusion shapes just as well. Astra clearly stood apart on one task: finding the copying heads inside a transformer.

The key finding: the gain tracks answers that finish

Every run lands near one line: accuracy rises with the share of answers that finish before the token limit. The post's runs are from its released evaluation files: the unedited model, then Astra's edits after 10, 25 and 50 rounds. The unedited model is right on nearly every answer it does finish; it just rarely finishes.

The post's own numbers show this. Unedited, the model finishes 7% of its answers and scores 7.9%; after Astra's edit it finishes 67% and scores 48.1%. Turning thinking off gets the unedited model to the same place, 68% finished and 45.2% correct, with no edit at all.

We built scrambled versions that keep every weight value but destroy the structure a real reader would rely on.

The Breakout result isn't a failure of the models. The game is identifiable without the board layout: the output layer shows only left and right matter, and exactly 8 input cells carry the paddle. Opus and Fable both noticed the shuffle. But it means part of the game task is counting, not reading a board.

3. Re-running the released results

How far our re-run landed from each number in the post. The shaded band is ±5%.

MinAtar: mean score over 1,000 episodes of the official game. Go: win rate over 400 games against the same-size PPO networks the post released, with our own engine built from the prompt's rules. The post's headline Go opponents weren't released, so those rows aren't here. Go rows outside the band differ by about 2–3 points of win rate, within sampling noise (±2.4 points).

Astra's hand-written Breakout network (no training, no tools) scores about 500 per game; a simple follow-the-ball rule we wrote scores 7.9, and random play 0.6. That result is solid. The PPO networks it's compared with are small and reported as their best seed, so “beats PPO” means “beats this PPO”.

4. The car: 1,024 episodes, one outcome

Each square is a distinct way the episode ended across 1,024 runs. The level and physics are fully deterministic (episodes from different random seeds differ by exactly 0.0).

The edited policy does succeed every time, but every episode is the same 73-step run. “100% over 1,024 episodes” is one success, not 1,024. The edit is also bigger than “3.5% of weights changed” suggests: those weights grew about 25× in size.

The post reports MATH-500 rising from 7.9% to 48.1%. In the post's setup the base model almost never finishes: it keeps second-guessing itself (“Wait…”) until it runs out of tokens. So the gain comes from answers the base model never got to give. Getting a model to stop and answer is a useful fix, and it was done purely by editing weights. But 7.9% is a weak baseline rather than the model's real skill level. We tested the simplest alternative on a GPU: thinking off, the model card's other recommended setting, graded exactly as the post grades. The unedited model scores 45.2% and the edited model 44.2% (all 500 problems, one sample each, about ±2.2 points). So turning thinking off recovers nearly all of the post's gain without touching the weights, and in that mode the edit adds nothing. The authors' own evaluation code defines this setting, with a note that thinking “looped at 0.8B”, but the post reports no non-thinking numbers. The reported runs were also picked from several prompt versions, and the submission rule changed partway through.

What others have found

Others reached the same conclusion about the Qwen result before us. Our contribution is the controlled measurement: both models, same settings, same grader, all 500 problems.

  • The “it's a loop fix, not math” argument, made from the post's own 93% figure: Alan West on dev.to, “131,072 Weights, and None of Them Were a Math Lesson”, and R&D World, which also quotes Goedecke describing the edit as steering, an existing technique, and Honnibal on tool-access differences between experiments.
  • Hacker News commenters reported thinking-off scores of 52–55% for the unedited model, without a published evaluation. Our 45.2% under the post's grading points the same way.
  • An independent rerun of the edited model with thinking on reports 51.0% on the full set (ML-Intern-lab on Hugging Face), consistent with the post's 48.1%.
  • The Alan Turing Institute's replication of the weight-reading and network-writing experiments found Claude Opus close to Astra on reading tasks, matching what we saw, and had Astra write new MinAtar networks: Breakout and Asterix landed near the post's scores, Seaquest at about half.

How we did it

  • All weights and prompts came from the authors' public logs. We didn't run any of their code; scoring scripts and the Go engine are our own, built from the prompts' rules.
  • Astra was run through the Codex CLI with tools off, as in the post. Opus and Fable each ran as a fresh agent with the same prompt.
  • One Opus run on the transformer task happened while our machine was heavily overloaded and stopped after about 5 code runs, so treat Opus's score there as a lower bound.
  • Qwen: the thinking-off runs used vLLM on all 500 MATH-500 problems, one sample each, graded with math-verify on the last \boxed{} answer, as the post does. Thinking-on runs at the post's 32,768-token limit, with and without a forced answer at the limit, are running now; this page will be updated with them.
  • Every script, blind prompt, answer key and model answer is in the GitHub repo, so anyone can rerun or extend this.
